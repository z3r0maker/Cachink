> state on that branch.
> **Score before the fixes:** 6.5 / 10, a judgment, not a measurement: a sound design held down by one

## What the fixes need from the owner

1. **Before deploying:** check that production's `DEVICE_TOKEN_SECRET` and `CRON_SECRET` are at least
   32 characters. A shorter one now closes every device route and every cron (ADR-139 §6).
2. **`apps/mobile/eas.json`'s production profile passes literal `$PRODUCTION_*` strings.** EAS does not
   interpolate them, so a production build would ship with `$PRODUCTION_API_BASE` as its API base. The
   new release gate fails that build until real values are supplied.
3. **Do not redeploy `bug-report` expecting reports to arrive.** It now refuses when it cannot count,
   and it cannot count: its tables were never migrated and the service role holds no grant since
   ADR-138. Phones fall back to sharing the report as a file until N-81.
4. In `.claude/settings.local.json` on each machine, delete `Bash(bash)`, `Bash(nohup env:*)` and
   `Bash(python3 -c ':*)`, and decide whether `Bash(git:*)` should become read-only git commands.
5. The open tasks: N-82 (generate and store the OTA key), N-83 (approve the boards), X-10 (backups and
   a restore drill), and installing the Renovate app.

## Smaller things found and left

- `restablecerContrasena` hashes the new password before it checks the link, and it and the three
  other link-spending actions are not throttled. The token is 256 bits, so this is a cost concern, not
  a guessing one.
- `apps/backoffice/.../empresa/documentos/[id]` sets a `sandbox` policy that `next start` drops, because
  the console's proxy already set that header. The console's enforced nonce policy still blocks script
  in the document.
- `/api/staff/migraciones/archivos/[fileId]` puts a tenant-supplied filename into `Content-Disposition`
  unsanitised.
- Plan metering counts tickets by the device's `created_at`; a device's client row can arrive already
  approved with a credit limit.
- `logoUrl` is stored absolute, so under the enforced `img-src 'self'` a logo does not load on an origin
  other than `PORTAL_URL` (previews, localhost against shared data).

## What is solid

- Row-level security is enabled and forced on all 45 `public` tables; the tenant claim is a
  parameterised, transaction-local setting; DELETE is revoked on ledger tables; the app role cannot
  read password hashes.
- Portal sessions are opaque, hashed at rest, expiring and revocable; login and activation are
  throttled in Postgres and answer alike for a wrong account and a wrong secret; reset and magic links
  are 256-bit, single use and hashed.
- The Stripe webhook verifies the signature over the raw body and is idempotent by event.
- The console uses a `__Host-` strict cookie, an enforced nonce CSP, mandatory TOTP with a replay
  guard, and an append-only audit log.
- CI pins every action by commit, runs with read-only permissions and a frozen lockfile, scans for
  secrets on every PR, runs CodeQL, and has no agent and no `pull_request_target`. No secret was found
  in tracked files.
- No `dangerouslySetInnerHTML`, open redirect, server fetch of a user URL, or SQL built from input in
  the portal or the console. The one LLM module has no callers.
- On the phone the token is in SecureStore, the entitlement is Ed25519 on a server-anchored clock, and
  there is no WebView or dynamic code.

## What could not be verified from the repository

- Supabase: that the Data API is off (`pnpm --filter @xangarro/data-pg check:data-api`), the role in
  production's `DATABASE_URL`, backups and a tested restore.
- Vercel: the length and distinctness of the production secrets; `PORTAL_URL` set; `ADMIN_DIAGNOSTICS`
  off.
- Two-factor and publish rights on EAS, Vercel, Supabase, Stripe, GitHub, the registrar and
  Cloudflare; branch protection and secret-scanning push protection.
- Whether `bug-report` is deployed.
- The phone on a device: the keychain move under a real screen lock, the generated Android manifest,
  the EAS build hook. Maestro flows were not run.
- An outside penetration test. A static read does not replace one before launch.
